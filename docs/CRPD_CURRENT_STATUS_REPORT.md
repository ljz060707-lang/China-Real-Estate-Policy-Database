这是一份给项目使用者看的说明。数字取自最近一次真实检查；抓取任务仍在后台继续，因此 Dashboard 中的数字可能继续增加。

## 先说结论

CRPD 现在已经是一个可以自己持续运行的政策采集系统：它按城市、年份和来源分成许多小任务，边抓边保存，失败后可以接着跑，不需要每次从头开始。

当前主要任务是先快速收集近五年的政策原文和附件，新的 AI 分类暂时关闭，避免分类过程拖慢收集。已有的分类结果保留，后续可以单独处理。

Dashboard “停留在八月”的问题已经修好。现在页面优先读取近五年任务的真实状态、最新日志和实际运行进程，不再只显示旧的通用状态文件。

## 系统到底怎么工作

可以把整个过程理解成下面这条流水线：

```text
已核验的官方来源
        ↓
按城市 × 年份 × 来源拆成小分片
        ↓
并发抓列表、正文和附件
        ↓
识别格式、清理正文、保留原始证据
        ↓
按 URL、版本和内容指纹去重
        ↓
写入 Curated 数据层并保存 checkpoint
        ↓
Dashboard 展示城市、年份、来源和缺口
```

具体来说：

1. 系统先使用来源注册表中的官方入口，不把搜索结果直接当成政策。
2. 每个城市再按年份和来源切成很多分片。一个分片完成后就记录下来，下一次只接着未完成的分片。
3. 抓取时同时处理列表页、详情页和附件，但每个网站保持限速，避免给政府网站造成突发压力。
4. 内容先保留原始版本，再清洗标题、日期、正文和链接。打不开、疑似错误页或格式不对的内容不会冒充有效正文。
5. 相同链接、相同版本或相同正文会通过内容指纹识别，避免重复入库；不同版本仍然保留历史。
6. Dashboard 只读真实数据库、Parquet、日志和状态文件，不使用模拟数字。

## 之前做过的关键优化

### 1. 统一迁到 E 盘

现在的正式程序和数据都在 E 盘：

- 程序：`E:\policy-database`
- 数据：`E:\Data Set\CRPD`

任务明确使用 E 盘路径，并禁用代理继承；不会因为当前 PowerShell 或旧 D 盘目录而悄悄切回旧数据。

### 2. 分片抓取，避免“一条任务卡死全局”

以前如果一个复杂来源卡住，容易让整个任务看起来没有进展。现在按“城市—年份—来源”拆分，某个分片失败只留下失败记录并让出执行权，其他城市可以继续。

### 3. 有限并发，而不是无节制轰击网站

当前近五年任务使用有限并发抓取，并对单个域名限为 1 个并发请求。这样比单线程快很多，同时控制 403、429、超时和网站压力。

重要的是：网络抓取可以并发，但正式数据写入仍沿用单写入链和锁，避免数据库相互覆盖。

### 4. 断点续跑和安全停止

分片、城市和运行状态都会保存 checkpoint。电脑重启、网络短断或任务暂停后，可以从已保存位置恢复；不会因为一次异常就把已有成果清掉或从零开始。

停止操作也是“请求安全让出”，等当前安全边界完成后退出，不粗暴杀掉正在写数据库的进程。

### 5. Parser v3：先判断文件是什么，再解析

解析器会优先看文件签名和真实格式，区分 HTML、PDF、Office/OLE、ZIP 等内容，并清理网页导航、错误提示等噪声。这样可以减少把错误页、下载提示或乱码当成政策正文的问题。

### 6. 原始证据、版本和哈希都保留

原始抓取内容不覆盖；URL、最终 URL、抓取时间、HTTP 结果、内容哈希和版本关系都会保留。后续发现解析问题，可以回到原始证据检查，而不是只能相信清洗后的结果。

### 7. PDF 和附件不再阻塞正文主流程

附件会登记、下载、哈希和关联到正文；暂时失败的附件进入待重试状态，不会拖住已经成功抓到的 HTML 正文。当前库中已经保留附件和 PDF 的发现、归档及解析记录。

### 8. 采集和分类分开

当前运行以“先把政策找全、存稳”为主，`skip_ai=true`、新的分类关闭。这样不会把 API 等待时间误认为抓取没有进展，也不会为了赶进度生成没有依据的标签。已有动作和历史 AI 结果继续保留。

### 9. Dashboard 改为读取真正的当前任务

页面现在会综合：

- 近五年任务状态文件；
- 最新运行日志；
- 计划任务状态；
- 实际进程和运行目录；
- Curated 数据和 Parquet 快照。

因此“当前城市”和“历史抓取”会随任务实际轮转更新，而不是固定停在旧的八月快照。

### 关于你看到的 `strict_complete=0/105`

这不表示该年份没有抓到数据。它表示：目前还没有城市在该年份同时满足全部严格完整性条件。抓取层仍可能已经有很多分片和文档，所以应同时看：

- 文档数是否增加；
- 分片是否增加；
- 有文档城市数是否增加；
- 还有哪些具体缺口。

换句话说，`strict_complete` 是“质量门槛完成度”，不是“抓到了多少网页”。

## 现在如何查看

打开 Dashboard：

```powershell
Start-Process "http://127.0.0.1:8501"
```

检查 Dashboard 是否正常：

```powershell
Set-Location E:\policy-database
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\check_dashboard.ps1
```

查看近五年任务状态：

```powershell
Get-ScheduledTask -TaskName "CRPD-Recent-5Y-Full-Crawl"
Get-Content "E:\Data Set\CRPD\automation\RECENT_5Y_FULL_CRAWL_STATE.json"
```

安全停止（请求任务在安全边界退出）：

```powershell
New-Item -ItemType File -Path "E:\Data Set\CRPD\control\STOP_FULL_SYNC" -Force
```

从已有 checkpoint 恢复：

```powershell
Set-Location E:\policy-database
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\resume_recent_5y_after_safe_stop.ps1 `
  -DataRoot "E:\Data Set\CRPD" `
  -TaskName "CRPD-Recent-5Y-Full-Crawl" `
  -PollSeconds 5
```

## 一句话理解这个项目

CRPD 不是“一次运行完的下载脚本”，而是一条可以长期运行的流水线：先登记可信来源，再分片抓取，边抓边保存原始证据，自动去重和恢复，最后用 Dashboard 告诉我们已经有什么、还缺什么，以及下一步该补哪里。

本报告只整理说明，不代表 105 城或所有年份已经完成；任务和历史数据继续保留在 E 盘运行。
