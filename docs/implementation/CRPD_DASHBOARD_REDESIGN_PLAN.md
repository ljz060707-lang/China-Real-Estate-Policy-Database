# CRPD Dashboard 信息架构与重设计方案

本方案以 `CRPD_DASHBOARD_DATA_INTERFACE_AUDIT.md` 的实测结果为依据。改造目标是建立“可解释、可核验、低干扰”的政策数据研究工作台，不改变 crawler、scheduler、source registry 或自动化状态机。

## 1. 统一只读数据模型

新增 `policydb.dashboard_live_state`：

- 每次刷新构建一个 `DashboardSnapshot`；
- 同一快照包含 system、crawler、coverage、documents、quality、AI、review、archive 八个域；
- 实时域读取 `pipeline_progress_events.parquet`、`crawl_shards.parquet` 和 automation JSON；
- 覆盖域读取 source slots、city/year progress、gaps；
- 文档域只读取必要列，不扫描 raw HTML 或完整正文；
- 文件按 mtime 缓存，事件只取最新窗口；
- 文件缺失、原子替换瞬间或 schema 不兼容时返回明确 unavailable/stale 状态，不抛出到页面。

状态对象中的每个指标均记录来源、定义和更新时间。时间统一从 UTC 转换为 Asia/Shanghai。

## 2. 数据库读取策略

1. 首先解析并显示权威 E 盘数据库路径。
2. 每次应用启动只做短连接的代表性健康查询，不持有数据库长事务。
3. 正式库视图可用时，政策中心使用参数化、分页、限量查询。
4. 正式库锁定或视图失效时，显示“数据库正在更新/索引待刷新”，其余实时监控页面继续工作。
5. 可选派生查询缓存必须位于 Dashboard runtime/output，引用 E 盘 Curated，只读服务页面；不得覆盖正式数据库。

## 3. 六个一级页面

### 3.1 总览

- 顶部系统状态条：任务状态、当前阶段、城市、月份、来源、心跳、PID。
- 关键指标：政策文档、已处理分片、525 来源门控、城市覆盖、年份覆盖、开放缺口。
- 抓取进度与严格完整性并列，不混用百分比。
- 当前任务详情、105 城处理进度、数据增长、最近 20 条中文事件。

### 3.2 政策中心

- 日期、地区、分类、发布主体、正文/PDF/审核状态筛选。
- 查询按钮触发；服务端分页与受限导出。
- 列表与详情分离，详情展示正文摘要、动作、来源、版本和附件。
- Gold 政策强度默认显示“尚未启用”，空值不显示为 0。
- 数据库不可用时展示降级说明，不显示堆栈。

### 3.3 采集与处理

- 当前实时采集、处理流水线、运行历史。
- 105 城矩阵与城市×年份矩阵。
- 当前分片进度使用已完成分片/已规划分片；严格 city-year 门控单独展示。
- 结构化 Dashboard job request 操作中心保留二次确认，不接受任意 shell。

### 3.4 数据质量与覆盖率

- 城市、来源角色、年份、正文、归档、附件与新鲜度分项。
- 质量问题与 gap 统计；`SKIPPED_DEPENDENCY` 不计为真实失败。
- 错误原因 Pareto 与可下载的受限表格。
- 所有比例显示分子、分母、百分比、定义和更新时间。

### 3.5 人工审核

- 来源候选、文档字段、AI 低置信度、异常与冲突分区。
- AI 结果明确标注为建议，不作为 ground truth。
- 写操作沿用正式 review service 与审计历史；只读模式禁用。

### 3.6 系统与设置

- 数据库、crawler、scheduler、provider、archive、磁盘、automation/AI/PDF 状态。
- 默认只显示路径别名和健康结果；内部完整路径放入折叠诊断区。
- 不显示密钥、Authorization、敏感 header 或密钥片段。

## 4. 视觉系统

- 背景使用浅中性色，内容区以表格、分隔线和紧凑信息带为主。
- 南京紫 `rgb(95, 0, 128)` 只用于选中态、关键链接和少量强调。
- 标题层级收敛；避免大面积渐变、层层卡片、过度圆角和阴影。
- 表格密度约 7/10，视觉变化约 4/10，动效约 2/10。
- 适配 1366/1920/2560 宽度；窄屏允许侧栏折叠。
- 状态不仅依赖颜色，始终附中文文字或图标。

## 5. 中文与格式化

建立统一 formatter：

- `format_value`：空值为“暂无数据”，列表/字典不直接输出 Python repr；
- `format_status`：内部枚举映射为中文，未知枚举显示“未识别状态”并保留可审计代码于折叠区；
- `format_datetime`：统一 Asia/Shanghai；
- `format_percentage`：必须有可信分母，无分母返回“暂无数据”；
- `format_count`：千分位；
- `format_path`：默认显示语义别名，完整路径只在诊断区显示。

## 6. 刷新与性能

- 默认实时刷新间隔 20 秒，可配置 15–30 秒。
- 仅总览和采集页启用自动刷新；政策列表、详情和审核表不自动重查。
- Parquet 读取按文件 mtime 缓存；每次只选择所需列。
- 最近事件只保留最新窗口；不在页面刷新时递归扫描 E 盘。
- Policy Center 查询必须有按钮、分页和上限。

## 7. 测试与验收

自动测试覆盖：

1. E 盘路径解析；
2. 实时事件与当前分片关联；
3. UTC 转北京时间；
4. 状态中文映射；
5. 空值和百分比语义；
6. 城市聚合与 105 城矩阵；
7. Parquet/JSON/DuckDB 不可用降级；
8. 六页导航 smoke；
9. 无密钥或原始敏感结构输出；
10. 严格完整性与实时进度不混用。

真实验收使用当前 E 盘数据，确认页面显示福州市当前月度分片和最新事件，且事件更新无需重启 Dashboard。随后进行三轮 UI 审查：结构批评、数据/语言审计、视觉细化。
